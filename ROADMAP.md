# Roadmap

What the Shuttlecraft mod has, and what comes next, in order.

`README.md` says what the mod does. `DESIGN.md` says how to change the ship.
`DEV_GUIDE.md` says how to work on it without breaking it — **read its "Rules
that exist because they were broken" before starting anything below.** Most of
these features touch an engine API this mod has not used yet, and every expensive
bug so far has been a plausible call that failed silently.

---

## Done

### Foundations — 1.0

- **The hull.** A 3×5-tile world model (`TREK_Shuttle.x`), generated by
  `tools/gen_shuttle.py`, set down on any clear ground.
- **Landing.** A sliced footprint search that finds clear ground near a chosen
  site without locking the game, exempts the player's own square, and beams the
  player back aboard if it gives up.
- **The transporter.** Beam up from anywhere and down beside the ship.
- **The cabin.** Generated at runtime in an unused cell (96,40), chunk-gated so
  nothing is built before it streams in, with the surrounding wilderness
  stripped to black void.
- **The phaser.** A sidearm kept charged, unjammed and unworn by
  `TREK_Phaser.lua`, with its own pulse sound and icon.
- **Ghost sweep.** Hulls left behind where the ship used to be are cleared when
  their chunks next load.

### Flight — 1.1

- **Hands-on piloting.** WASD flight above buildings and trees with a rotating
  3D craft and a projected shadow (`TREK_Flight.lua`).
- **Helm window** with bookmarks, map picking and landing
  (`TREKHelmWindow` in `TREK_Travel.lua`).
- **Separate dev identity.** `tools/deploy_windows.py` installs as
  `TrekShuttleDev` so a subscribed Workshop copy cannot shadow a test build.

### The interior — 1.2 (current)

- **BuildingEd-authored cabin.** The interior is designed in the map editor
  (`design/buildinged/TrekShuttle_Interior.tbx`) and read at runtime from
  `TREK_InteriorLayout.lua`: helm consoles and viewscreen forward, galley to
  port, eight lockers to starboard, berth aft.
- **Every container stocked — confirmed in game.** 19 containers filled by
  weight to at least half their own capacity: sick bay ×2, engineering ×2,
  provisions, **phaser locker**, armoury, survival kit, plus fridges, ovens,
  microwave and counters. New `weapons` and `survival` loot lists.
- **Three silent bugs found and fixed**, each written up in `DEV_GUIDE.md`:
  containers built without an `ItemContainer`; items created through
  `InventoryItemFactory`, which is not a Lua global in build 42; and a water
  top-up using the fluid API on a sink that only has reserve water.
- **Infinite water.** The galley sink is kept full while aboard and survives
  the vanilla mains shutoff. *Awaiting in-game confirmation — `TREK_Water()`.*
- **Diagnostics.** `TREK_Stock()` and `TREK_Water()` report from the debug
  console; every build logs a manifest line per container.
- **Tests that check the real ship.** `test_layout.py` loads the authored layout
  and cross-checks it against the `.tbx`; `test_stock.py` stubs the engine as it
  actually behaves and fails if items cannot be created.
- **Workshop packaging owns the published id.** `tools/package_workshop.py`
  carries `WORKSHOP_ID = 3801178990` and refuses to stage an upload that would
  create a second item.

## How art gets made

**All icons and images are generated and vetted with the FlowDot Gemini Image
toolkit** (`gemini-image`, installed and credentialed). It has four tools, and
the loop uses all of them:

| Step | Tool | Purpose |
|---|---|---|
| Create | `generate-image` | Text → image from a written brief |
| Refine | `edit-image` | One image + instruction → revised image |
| Combine | `compose-images` | Two images → one (e.g. an insignia onto a panel) |
| **Vet** | `analyze-image` | Image + instruction → written critique |

**Vetting is a step, not a glance.** Every asset goes through `analyze-image`
with a checklist before it enters the mod:

1. Does it read at the size it will actually be shown? Item icons are drawn at
   roughly 32×32 in the inventory — **vet a downscaled copy**, not the original.
2. Is the silhouette distinct from every other icon in the mod?
3. Is it recognisably Star Trek without copying a specific frame of the show?
4. Is the background genuinely transparent?

That last one needs a tool of its own: image models usually paint a background
rather than output alpha. The `fal-ai` toolkit (also installed) has background
removal, and its image-to-3D mesh generation is the likely route for the
replicator and EMH models below — feeding `tools/import_gltf.py`, which already
exists.

Every generated file then gets the same static treatment as the rest of the
mod: named for `media/textures/Item_<Icon>.png`, referenced from the item
script, and checked by `tests/test_assets.py`.

## Built, awaiting in-game test: the helm console

`TREK_Helm.lua`. An LCARS panel drawn from tinted shape textures
(`tools/gen_helm_ui.py`) over a Gemini-generated backdrop and emblem, both
vetted with `analyze-image` at in-game size; the finished console was vetted
the same way from a render made by `tools/preview_helm.py`.

- **Shields** up/down, on by default, saved with the world.
- **Flight speed** 1/4x, 1/2x, 1x, 2x, 3x, 5x, applied live.
- **Navigation** unchanged, plus **Course to map crosshair**.
- **Controllers and Steam Deck**: stick walks the buttons, A presses, B closes,
  Y hands the stick to the map (pan, triggers zoom, A lays in a course on the
  crosshair), LB/RB step the log.
- `tests/test_helm.py` drives it against stubbed vanilla UI, including every
  controller path.

**Open question:** the emblem's reviewer judged it a near-exact copy of the
Picard-era Starfleet insignia. The mod is already labelled an unofficial fan
work; whether to keep it or have Gemini draw something more distinct is a
call for the author.

The original plan for the console follows.

## Plan: the helm console

The first job. The existing `TREKHelmWindow` is a functional vanilla panel; this
turns it into the ship's bridge.

**Star Trek–themed art.** LCARS-style panel backgrounds, buttons and frames,
generated through the loop above and drawn as textures in `media/ui`. Build it
from separate pieces (frame, button states, header) rather than one flat image,
so the panel can resize and buttons can show hover and pressed states.

**Controls:**

- **Shields — up / down.** On by default. No radius control; just the state.
  `Core.repelZombies` and `C.FieldRadius` already implement the field, so this
  is a persisted flag in `U.state()` that the field checks, plus the toggle.
  Needs a decision on what "down" means: no field at all, or the field only
  while landed.
- **Every existing helm control** for choosing and travelling to a new
  location — bookmarks, map pick, set destination, land. Nothing removed, all
  reskinned.
- **Travel speed.** From much slower than today to **5× current speed**.
  `C.FlightSpeed` (1.50 squares per tick) becomes a base, multiplied by a
  persisted setting — roughly 0.25× to 5×. **Test the top end before shipping
  it:** at 7.5 squares per tick the ship outruns chunk streaming, and landing
  already has to wait for ground to load. The landing timeout may need to scale
  with speed.

**Difficulty: Medium.** The panel and both controls sit on proven machinery.
The real work is the art pipeline, which this is the first use of — so it
doubles as the test run for every item below.

## Then: items

Mostly icon work, with a few genuine systems mixed in. Grouped roughly from
cheapest to most involved.

### Food

- **Starfleet ration pack** — high nutrition, high happiness.
  Item script + icon. **Trivial.**
- **Gagh** *(Klingon serpent worms, served live)* — high nutrition. An
  unhappiness penalty for anyone who isn't Klingon would be very in-lore.
  **Trivial.**
- **Leola root stew** — Neelix's most famous dish, and famous largely because
  the crew couldn't stand it. High nutrition, a small happiness *penalty* is
  the joke. **Trivial.**

All three go into the galley `C.Loot` lists as well as the replicator menu.

### Medical

- **Hypospray** — a strong treatment, and possibly a **cure for being bitten**.
  The item is easy; the cure is a design call, because curing zombie infection
  changes what kind of game the mod makes. Worth deciding deliberately —
  single use, rare, or replicator-only are all ways to keep it special.
  **Medium** — *verify first*: the build 42 `BodyDamage` API for clearing
  infection per body part. Check `pzapi.py` **and** grep vanilla Lua for a real
  call site before trusting a method name.

- **Medical tricorder** — full medical diagnosis of yourself or a target,
  regardless of the Doctor skill. The vanilla health panel hides detail by
  skill, so this is a custom panel that reads the body parts directly and shows
  everything. **Medium.**

### Tools

- **Tricorder** — unlocks locks, and sensor-sweeps for items and other
  information. The sweep reuses the square-walking pattern from
  `Core.repelZombies`; results via `U.note` or a small panel. **Medium** —
  *verify first*: the lock API on doors and windows. Keep the sweep **sliced**
  (see *Slice any search that touches thousands of squares* in DEV_GUIDE).

### Ship systems

- **Replicator** — a modelled galley fixture with its own custom UI that can
  make **basically any item**. Overpowered, and in lore.
  - **Model:** generated via fal.ai image-to-3D, or sourced (with a licence the
    mod can carry — see the hull's CC BY credit), then imported through
    `import_gltf.py`. Placed as a world model like the helm console.
  - **UI:** searchable, categorised list of every item in the game — the
    catalogue is large, so search matters more than browsing.
  - **Making items:** `instanceItem(id)` into the player's inventory — the path
    already proven by the lockers.
  - **Hard part:** enumerating every item at runtime. *Verify first* how build 42
    exposes the item script list to Lua.
  - **Difficulty: Medium–Hard**, mostly UI.

- **EMH** — the Emergency Medical Hologram.
  - A **wall-mounted switch**, like a light switch. A vanilla switch sprite with
    a tag and a context menu avoids needing a custom tile.
  - Activating it spawns a **simple static model** of the Doctor beside the
    switch — a world model, the same pattern as the helm console. Not an NPC,
    not animated.
  - A **dialogue interface** with his classic lines ("Please state the nature of
    the medical emergency").
  - Provides the medical tricorder's full diagnosis **and treatment**, with
    **infinite medical supplies**.
  - Deactivating removes the model.
  - **Difficulty: Medium–Hard.** Each piece is modest; there are simply several.
    Should come after the hypospray and medical tricorder, since it reuses both.

## Suggested order

1. **Helm console** — first use of the art pipeline; everything after benefits.
2. **Food** — three icons, no systems. Fast confidence in the pipeline.
3. **Medical tricorder, then hypospray** — decide the bite-cure question here.
4. **Tricorder** — unlocking and sweeping.
5. **Replicator** — the biggest UI job.
6. **EMH** — builds on the medical items.

---

## Ground rules for everything above

- **Verify every new engine call two ways** — `python tools/pzapi.py` for
  whether it exists, and a grep of the game's own `media/lua` for whether Lua
  may call it. The jar is not the API.
- **Add the log line that proves it worked.** `TREK_Stock()` ended three
  sessions of guessing in one grep. Every new system gets its own.
- **Bump `C.BuildRev`** for anything that places or changes an object in the
  cabin (replicator, EMH switch). Item-only changes don't need it.
- **Extend the static tests** in preference to in-game checks.
- **Nothing ships to the Workshop until it has been seen in game.**
